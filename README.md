# Cross-Lingual News Consistency Checker (NewsNLI)

Detects when international news outlets contradict each other — in any
language, without translation. Built as a capstone project for **SemEval-2022
Task 8: Multilingual News Article Similarity**, framed as a 3-way Natural
Language Inference (NLI) task: given two news sentences (possibly in
different languages), classify their relationship as **Entailment**,
**Neutral**, or **Contradiction**.

Two multilingual transformer models are fine-tuned and compared:
`mBERT` (`bert-base-multilingual-cased`) and `XLM-R`
(`xlm-roberta-base`), with a Streamlit app for interactive, side-by-side
inference.

## The Pipeline (research/)

The three notebooks are the actual, working pipeline — run them **in order**
the first time you set up the project:

1. **`01_data_cleaning.ipynb`**
   Reads `data/raw/final_dataset.csv` (15,662 same-language rows) and
   `data/raw/final_dataset_1.csv` (50,000 cross-lingual rows), cleans them,
   and writes `data/processed/combined_clean.csv`.

2. **`02_eda_improved.ipynb`**
   Exploratory analysis + augmentation on the cleaned data
   (`data/processed/combined_clean_augmented.csv`), then splits into
   `data/splits/train.csv`, `val.csv`, and `test.csv`. EDA figures are saved
   to `data/figures/`.

3. **`03_model_training_and_evaluation.ipynb`**
   Fine-tunes each model in `MODELS_TO_TRAIN` (currently `mbert` and `xlmr`;
   `infoxlm` and `mdeberta` are present but commented out) on
   `data/splits/`, saves checkpoints to `models/`, and writes all evaluation
   outputs (8 metrics per model, per-language-pair F1, prediction CSVs, and
   figures) to `evaluation/`.

**Important:** `data/raw/`, `data/processed/`, `data/splits/`, `models/`,
and `evaluation/`'s underlying CSVs/checkpoints are not included in this
package (too large / regenerated by the notebooks) — only the folder
structure (via `.gitkeep` files) is included. You'll need to add your
original `final_dataset.csv` / `final_dataset_1.csv` to `data/raw/` before
running notebook 01.

## Quick Start

### Step 1 — Create a new environment
```bash
conda create -n news_nli python=3.11
```
> The original README specified `python=3.14`. At the time of writing,
> PyTorch/Transformers/Accelerate wheels typically lag several months
> behind the newest CPython release — 3.11 is a safer, well-supported
> choice for this stack. Adjust if you've already confirmed 3.14 works
> with your installed package versions.

### Step 2 — Activate the environment
```bash
conda activate news_nli
```

### Step 3 — Install dependencies
```bash
pip install -r requirements.txt
conda install -c conda-forge plotly
```
> First install takes 3–5 minutes (PyTorch + Transformers are large).

### Step 4 — Run the pipeline (first time only)
Run `research/01_data_cleaning.ipynb` → `02_eda_improved.ipynb` →
`03_model_training_and_evaluation.ipynb`, in order, after adding your raw
CSVs to `data/raw/`.

### Step 5 — Launch the app
```bash
streamlit run app.py
```
The app auto-detects the `models/` directory produced by notebook 03.

## About `src/news_nli/`

This package follows the structure originally declared in `template.py`
(components / config / constants / entity / logging / pipeline / utils),
which existed in the project but had never actually been built out — the
folders and most files simply didn't exist yet. This restructuring creates
them, with working boilerplate for the generic, reusable pieces:

- **`logging/__init__.py`** — a ready-to-use `logger`, writing to both the
  console and `logs/running_logs.log`.
- **`utils/common.py`** — `read_yaml()`, `create_directories()`, `get_size()`.
- **`constants/__init__.py`** — paths to `config/config.yaml` and `params.yaml`.
- **`entity/config_entity.py`** + **`config/configuration.py`** — typed
  config objects (`DataConfig`, `ModelTrainingConfig`) loaded from
  `config.yaml`/`params.yaml`, with values already matching what
  `research/03` uses today (5 epochs, batch size 16, lr 2e-5, etc.).

**`components/`, `pipeline/`, and `entity/__init__.py` are intentionally
left as empty package markers.** The real model-training/evaluation logic
still lives in the research notebooks — turning that into proper
`src/news_nli/components/*.py` modules (data ingestion, model training,
evaluation as separate, testable steps) is a natural next refactor, but is
a separate task from this restructuring and wasn't invented here to avoid
duplicating/diverging from the working notebook logic.

## Notes on What Changed in This Restructuring

- **`evaluation1/` → `evaluation/`.** The notebooks already write to
  `../evaluation` (`EVAL_DIR = Path("../evaluation")` in notebook 03) — the
  folder in the original package was named `evaluation1/`, which didn't
  match. Renamed so the tracked outputs actually correspond to what the
  code produces.
- **Removed `research/.ipynb_checkpoints/03_model_training-checkpoint.ipynb`.**
  This was not a meaningful second version of the notebook — it was a
  2-cell, ~2KB Jupyter *autosave* artifact from a very early point in the
  notebook's history (just a GPU-availability check), while the real
  notebook (`03_model_training_and_evaluation.ipynb`) is the complete,
  ~370KB, 17-cell version. `.ipynb_checkpoints/` folders are autosave
  scratch space Jupyter creates locally — they were never meant to be
  committed. Added `.ipynb_checkpoints/` to `.gitignore` so this doesn't
  recur.
- **Renamed `03_model_training and evaluation.ipynb` → `03_model_training_and_evaluation.ipynb`**
  (removed the space, for cleaner cross-platform paths/URLs).
- **Added the missing `data/`, `models/`, `logs/`, `.github/workflows/`,
  `config/`, and `src/news_nli/` structure** that `template.py` already
  declared as the intended layout but that had never been generated.
- **`.gitignore`** now also excludes `.ipynb_checkpoints/` and the
  data subfolders' contents (keeping `.gitkeep` placeholders so the
  folder structure itself stays tracked).
